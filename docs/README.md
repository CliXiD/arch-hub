# Project documents

The hub's documents are the project's **source of truth**. The factory, `/grill-issue` and
every agent read them before anything else. When something elsewhere (a GitHub issue, a
ticket, a chat message, an old wiki page) repeats or contradicts them, these documents win;
a contradiction is flagged for a human, never silently "fixed" in favour of the issue.

Order of trust, highest first:

1. `docs/` in the hub: BRD, specs, ADRs (and the hub `AGENTS.md`)
2. The code and docs in each repo under `repos/`
3. The hub issue being built (scope for one job, not a change to the documents)
4. External sources, through their snapshots in `docs/sources/` (never the live page)

`docs/history/` is below all of these: it records why past jobs changed things (their issue,
spec, build, reviews and decision), not how the system works now. Read it to understand a
change; never follow an old job's spec over the current BRD, specs and ADRs.

## Layout

```
docs/brd.md                 Business requirements: why, for whom, what (BR-xxx, NFR-xxx)
docs/specs/NNN_<area>.md    System specs, numbered in reading order (SPEC-<area>-xx)
docs/specs/README.md        Their table of contents, generated by `factory/bin/docs index`
docs/adr/NNNN-<slug>.md     Architecture decisions (ADR-NNNN), one per decision
docs/sources/sources.json   Registry of every external source (S-xxx): kind, link, hash, fetched date
docs/sources/S-xxx.md       Snapshot of the source as last read (S-xxx.prev.md: the one before)
docs/history/<job-id>/      The record of every finished factory job (written by factory/bin/job)
docs/history/README.md      Their index, newest first
docs/_templates/            brd.md, spec.md, adr.md
```

## Conventions

- **IDs.** Define an item once, in bold at the start of a list item or a heading:
  `- **BR-004** Customers can download a receipt as PDF.` Refer to it anywhere as `[BR-004]`.
  Sources are `[S-003]`, ADRs `[ADR-0007]`, spec items `[SPEC-billing-03]`.
- **Cite where it came from.** Every BRD item and every ADR context cites at least one
  source (`[S-003]`) or says `Source: decided in /hub-init on <date>` (or the grill session).
- **Snapshots, not live links.** Agents read `docs/sources/S-xxx.md`. `/docs-sync` re-reads
  the original, records a new snapshot when it changed, and proposes edits to everything
  that cites it.
- **Specs are read in order.** `NNN_<area>.md` (`001_registration.md`, `002_policies.md`, ...): the
  flows the rest depends on first, then in the BRD's order. Create one with
  `factory/bin/docs spec-new "<area>"`, then `factory/bin/docs index`. Reordering renames files
  only (`git mv`); the `SPEC-<area>-xx` ids and every citation stay the same.
- **ADRs are append-only.** Never rewrite an accepted ADR; supersede it with a new one
  (`Status: Superseded by [ADR-0009]`). Brownfield ADRs describing what already exists use
  `Status: Accepted (as-built)`.
- `factory/bin/docs check` validates IDs, citations, snapshots and staleness.

## Tools

```
/hub-init                      first-time: goal, sources, BRD, stack/ADRs, specs, repos
/docs-sync [S-xxx ...]         re-check sources, show what changed, propose updates
/grill-issue                   a new requirement → issues (and ADRs for new decisions)
factory/bin/docs list | check | cites <id> | add-source | record | adr-new | spec-new | specs | index
```
