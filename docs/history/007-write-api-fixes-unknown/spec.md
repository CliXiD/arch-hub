# Write API fixes: unknown owner 422, `api` source, kind-pair location

> Issue #18: Write API fixes: unknown owner is a 422, `api` source for service writes, kind-pair error points at the right field

## Summary
- An unknown `owner` on node create/update becomes `422 /problems/validation` at `body.owner` ("team does not exist"), checked before the caller's membership of that team, so editors stop getting a misleading `403`.
- Writes by a service-account token record `source: api` on the node or edge and in its `change_log` row; user tokens keep `ui` ([BR-004], [SPEC-model-08]). A new goose migration widens the three `source` CHECK constraints (expand only, no backfill, [ADR-0016]).
- A disallowed kind pair on `POST /api/v1/edges` reports `body.from` when the source node's kind starts no allowed pair of that edge type, otherwise `body.to` ([SPEC-model-04]).
- `api/openapi.yaml` gains `api` in its three `source` enums; `arch-web` regenerates `src/api/schema.d.ts`. No UI change.
- High risk: touches `change_log` constraints and the order of a permission check; a human signs off (Decision 4, Always escalate).

## Context

**arch-api**
- `arch-api:internal/model/write.go` holds every write. `CreateNode` calls `a.can(in.Owner)` *before* its transaction, then inside the transaction checks `q.TeamExists` and appends `{body.owner, "unknown team"}` to the collected `ValidationErrors` (only admins ever reach it). `UpdateNode` locks the node, checks `a.can(cur.Owner)`, then `a.can(*p.Owner)` when the owner changes, then the version, and later the same `TeamExists` / "unknown team" check. `record()` writes every `change_log` row with the constant `sourceUI = "ui"`; `CreateNode`, `UpdateNode`, `CreateEdge`, `UpdateEdge` also set `Source: sourceUI` on the returned entity. `DeleteNode` (cascaded edge rows), `DeleteEdge`, and team/environment writes go through `record()` too.
- `arch-api:internal/model/types.go` — `Actor{Subject, Username, Kind ("user"|"service"), Admin, Teams}`; Huma tags `enum:"ui,yaml,discovery,import"` on `Node.Source` (line ~70), `Edge.Source` (~84) and the history `Change.Source` (~230).
- `arch-api:internal/httpapi/routes_write.go` `actorFrom()` builds `model.Actor` with `Kind: p.ActorKind`; `arch-api:internal/auth/principal.go` already decides `ActorKind` (`auth.ActorUser` / `auth.ActorService`). No auth change is needed.
- `arch-api:internal/db/queries/write.sql` — `CreateNode`, `UpdateNode`, `CreateEdge`, `UpdateEdge` hardcode `'ui'` as SQL literals; sqlc generates `arch-api:internal/db/dbq/write.sql.go` (`make sqlc`, never hand-edited).
- `arch-api:internal/model/validate.go` `checkKindPair(edgeType, allowed, fromKind, toKind)` always returns `Location: "body.to"`, message `edge type %s does not allow %s → %s`. It already receives the `allowed []KindPair`.
- Constraints: `arch-api:migrations/00002_model.sql` declares inline `source text NOT NULL CHECK (source IN ('ui','yaml','discovery','import'))` on `nodes` and `edges`; `arch-api:migrations/00004_change_log.sql` the same on `change_log`. PostgreSQL names inline column checks `nodes_source_check`, `edges_source_check`, `change_log_source_check`. The `change_log` triggers fire only on `UPDATE`/`DELETE`/`TRUNCATE`, not on `ALTER TABLE`. Migrations are embedded via `//go:embed *.sql` in `arch-api:migrations/embed.go`; existing files are protected (`migrations/*`), so the change is a new file `00006_...sql`.
- Seed: `arch-api:internal/model/seed.go` writes `source: "import"`; unchanged.
- Tests: unit `arch-api:internal/model/validate_test.go` (`TestCheckKindPair`), handler tests with a `fakeWriter` in `arch-api:internal/httpapi/routes_write_test.go`; integration (build tag `integration`, testcontainers) in `arch-api:cmd/arch-api/write_integration_test.go` (`TestWriteIntegration`, with `editor`, `admin`, `viewer` and `service` token writers, helpers `changesSince`, `lastChangeID`, `problemBody.locations()`). It currently asserts `"ui"` on every history entry of `payments-api`, including the one the `service` writer makes in "service account writes", and the "kind pair not allowed" case (`runs_on` application → network) expects `body.to`.
- Docs: `arch-api:README.md` "Writes" section says `source` (`ui`) and "kind pair ... (`422` at `body.to`)".
- Seeded edge types (`00003_model_seed.sql`): `calls` allows `application → application`, `application → external` (and `external → application` once hub issue #17 lands); `runs_on` allows `application → infrastructure`.

**arch-web**
- `arch-web:src/api/schema.d.ts` is generated by `pnpm gen:api` (`openapi-typescript`, reads `../arch-api/api/openapi.yaml` or `$ARCH_API_OPENAPI`). It has three `source: "ui" | "yaml" | "discovery" | "import"` unions. Nothing in `src/` reads `source`.

## Contract

- **`source` enum** on `Node`, `Edge` and the history entry (`Change`) in `api/openapi.yaml`: `ui`, `api`, `yaml`, `discovery`, `import`. Additive; no field renamed or removed. Value written: `api` when the request's principal has `actor_kind: service`, `ui` when `user`. Rows written before this job keep their stored value (no backfill).
- **Unknown owner** — `POST /api/v1/nodes` (any `owner`) and `PATCH /api/v1/nodes/{environment}/{id}` (when `owner` is present and differs from the stored owner), roles editor and admin:
  ```json
  HTTP 422  Content-Type: application/problem+json
  {"type": "/problems/validation", "status": 422, "title": "Unprocessable Entity",
   "errors": [{"location": "body.owner", "message": "team does not exist"}]}
  ```
  (`title`/`detail` as the existing validation problems produce them; the `errors` array holds exactly that one entry.) Viewers still get `403` from the role check.
- **Kind pair** — `POST /api/v1/edges`: `422 /problems/validation`, one entry at `body.from` when no `allowed` pair of the edge type has `from == <source node kind>`, otherwise at `body.to`; message unchanged `edge type <type> does not allow <fromKind> → <toKind>`.
- **Schema:** new migration `arch-api:migrations/00006_source_api.sql` replaces `nodes_source_check`, `edges_source_check`, `change_log_source_check` with `CHECK (source IN ('ui','api','yaml','discovery','import'))`. No column, default, grant or nullability change. Owned by `arch-api` only [ADR-0004]; no other repo changes with it.
- **Env vars / config:** none.
- **Compatibility:** `arch-web` keeps working against the old and new API (it does not read `source`, and the new enum value only widens a union). The migration must be applied before the new binary writes `api`; the Helm migrate job and `dev/arch-api/start.sh` already run migrations before serving.

## Requirements

### arch-api

1. **Owner existence before permission (create).** In `CreateNode`, move the owner check into the transaction as its first step: `q.TeamExists(ctx, in.Owner)`; when false, return `ValidationErrors{{Location: "body.owner", Message: "team does not exist"}}` immediately (that single error, no other validation collected). Only then call `a.can(in.Owner)` (still before the remaining validation, so a member-less editor with an existing team still gets `403` before other validation errors). Remove the old in-transaction "unknown team" append.
2. **Owner existence before permission (update).** In `UpdateNode`, keep the order lock → `a.can(cur.Owner)`; then, when `p.Owner != nil && *p.Owner != cur.Owner`, check `q.TeamExists` and return the same single `body.owner` / "team does not exist" error when missing, then `a.can(*p.Owner)`, then the version check. Remove the later "unknown team" block.
3. **Source from the actor.** Add one helper in `internal/model` (for example `func (a Actor) source() string`) returning `"api"` when `a.Kind == "service"` and `"ui"` otherwise; define the `api` value next to `sourceUI` in the constants block. `record()` uses it for every `change_log` row (node, edge, cascaded edge deletes, team, environment), and `CreateNode`, `UpdateNode`, `CreateEdge`, `UpdateEdge` use it for the returned entity's `Source`.
4. **Queries.** In `internal/db/queries/write.sql`, replace the `'ui'` literal in `CreateNode`, `UpdateNode`, `CreateEdge`, `UpdateEdge` with a `sqlc.arg('source')` parameter; regenerate `internal/db/dbq` with `make sqlc` and pass the actor's source from `write.go`.
5. **Migration.** Add `migrations/00006_source_api.sql` (goose). `Up`: for each of `nodes`, `edges`, `change_log`, `ALTER TABLE ... DROP CONSTRAINT <table>_source_check, ADD CONSTRAINT <table>_source_check CHECK (source IN ('ui', 'api', 'yaml', 'discovery', 'import'));`. `Down`: restore the original four-value constraints, with a comment that it fails once any `api` row exists (`change_log` rows can't be changed). No backfill, no grant changes, no edit to existing migrations.
6. **OpenAPI enums.** Change the three `enum:"ui,yaml,discovery,import"` tags in `internal/model/types.go` to `enum:"ui,api,yaml,discovery,import"`; regenerate `api/openapi.yaml` with `make openapi`.
7. **Kind-pair location.** `checkKindPair` returns `Location: "body.from"` when no element of `allowed` has `From == fromKind`, otherwise `"body.to"`; message unchanged.
8. **Unit tests.** Make `TestCheckKindPair` table-driven and cover: allowed pair → nil; `calls` with `infrastructure → application` → `body.from`; `calls` with `application → infrastructure` → `body.to`; `runs_on` `application → network` → `body.to`. Add a table-driven test for the actor-to-source helper (`service` → `api`, `user` → `ui`).
9. **Integration tests** (`cmd/arch-api/write_integration_test.go`, `integration` tag):
   - `POST /api/v1/nodes` with `owner: "no-such-team"` as `editor` and as `admin` → `422`, type `/problems/validation`, `locations() == ["body.owner"]`, message `team does not exist`, no `change_log` row; `PATCH` of an editor-owned node to `owner: "no-such-team"` → same `422`.
   - The `service` writer creates a node (owner `platform`) → response `source: "api"`; its history (`GET /api/v1/history?entity=node&environment=prod&id=<id>`) shows `source: "api"`; an edge created by `service` has `source: "api"`; nodes and edges created by `editor` keep `"ui"`.
   - Edge cases: `calls` from an `infrastructure` node (for example `eks-prod`) to `payments-api` → `body.from`; `calls` from `payments-api` to `eks-prod` → `body.to`; the existing `runs_on` application → network case stays `body.to`.
   - Update the existing "history" assertion so the entry written by the `service` writer in "service account writes" expects `api` and the others `ui`, and assert `source: api` in "service account writes".
10. **README.** In `README.md` "Writes": `source` is `ui` for a user token and `api` for a service account; the kind-pair sentence says `body.from` when the source node's kind starts no allowed pair, otherwise `body.to`; the Permissions bullet notes an `owner` that is not an existing team gives `422` at `body.owner` ("team does not exist") before any team-membership check.

### arch-web

1. After the `arch-api` change is merged, regenerate `src/api/schema.d.ts` with `pnpm gen:api` (pointing `ARCH_API_OPENAPI` at the merged `openapi.yaml` if `../arch-api` is not at it). The only diff is `"api"` added to the three `source` unions. No other file changes; commit as `chore: regenerate the API schema for the api source`.

## Merge and deploy order

1. `arch-api` first: it owns the contract and the migration; deploy runs the migrate job before the new binary writes `api`.
2. `arch-web` second: its `schema.d.ts` is regenerated from the merged `openapi.yaml`. It is compatible with either API version, so deploy timing doesn't matter.
`arch-deploy`: no change. This follows `merge_order`.

## Out of scope

- Any UI that shows or filters by `source` (including the History tab), and any `arch-web` code beyond the regenerated file.
- Changing roles, team permissions, auth middleware or `actorFrom`/`PrincipalFromClaims`.
- Backfilling `source` on existing nodes, edges or `change_log` rows; any `change_log` grant or trigger change.
- YAML import and its `yaml` source; seed data (stays `import`).
- Mapping a team deleted concurrently with a node insert (FK violation) to a 422; editing existing migrations; using `NOT VALID`/`VALIDATE` or other migration tuning.
- Changing the kind-pair message text or the `allowed` pairs of any edge type.
- Hub docs edits inside this job (see Docs impact).

## Assumptions

- The unknown-owner error is returned on its own (early return), not merged with other validation errors in the same response — the issue says "one error at `body.owner`" and the check must precede the permission check, which itself precedes the rest of validation.
- On PATCH, the current-owner permission check stays before the new-owner existence check (intake Scope), so an editor who can't edit the node still gets `403` whatever owner they send.
- Team and environment writes (admin-only) also record `api` when made by a service account, because `record()` derives the source from the actor for every row — this is "every write through the write API by a service-account token".
- The new migration is `00006`; if another job lands a `00006` first, the builder takes the next free number.
- The `Down` migration restores the narrow constraints and is expected to fail once `api` rows exist; `change_log` is append-only, so a clean down is not possible after use.
