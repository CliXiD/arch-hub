# Build: Write API for nodes, edges, teams and environments with change log

## Summary
- arch-api can now create, update and delete nodes and edges (editor, scoped to the team, with `If-Match`, `412` and `428`) and teams and environments (admin, `409 /problems/in-use` with `count`). It also serves a node's history at `GET /api/v1/history?entity=node`.
- Every successful write adds one `change_log` row per entity in the same transaction. A no-op PATCH, or any rejected write, adds none. Two new migrations add the append-only table (a trigger rejects UPDATE, DELETE and TRUNCATE) and the `arch_app` grants.
- Attributes are checked against the type schema, and secrets are detected, by hand-written code with no new dependency. Values are never echoed or logged.
- arch-web only regenerates `src/api/schema.d.ts`.
- Round 1: first build. PRs: CliXiD/arch-api#5 and CliXiD/arch-web#5 (drafts, linked to each other).

## Changes

### arch-api
- `migrations/00004_change_log.sql` (new): the `change_log` table with the Contract's CHECKs, the `(entity, entity_key, at DESC, id DESC)` index, two partial expression indexes on edge `from`/`to`, the `change_log_reject()` plpgsql function, and BEFORE UPDATE OR DELETE (row) and BEFORE TRUNCATE (statement) triggers. Down drops them all.
- `migrations/00005_app_role_grants.sql` (new): grants to `arch_app` per Contract → Schema (USAGE on public; DML on the 6 model tables; SELECT, INSERT on `change_log`; USAGE, SELECT on `change_log_id_seq`; SELECT on `goose_db_version`). Down revokes each of them.
- `internal/db/queries/write.sql`, `history.sql` (new) and `internal/db/dbq/*` (regenerated by `make sqlc`): lock, insert, update and delete queries, node and edge counts, `InsertChangeLog`, and `NodeHistory` (three OR branches, one per index, keyset `(at, id) <`, `LIMIT limit+1`).
- `internal/auth/principal.go`: `Principal.Username` is `preferred_username`, or the client id for a service account. No other field changes. `principal_test.go` cases were extended.
- `internal/model/types.go`: `Actor`, the request bodies (`NodeCreate`, `NodePatch`, `EdgeCreate`, `EdgePatch`, `TeamCreate`/`Patch`, `EnvironmentCreate`/`Patch`, with Huma tags: id slug pattern; `additionalProperties: false` from Huma's default), `Change` and `HistoryPage`.
- `internal/model/errors.go`: `ErrConflict`, `ErrStale`, `ValidationErrors`, `ForbiddenError{Team}`, `InUseError{Count}` and `SecretError{Locations}`.
- `internal/model/write.go` (new): the 12 write methods. Each runs in one pgx transaction (`inTx`, via `s.q.WithTx`) and writes through the single `record` helper. Node and edge PATCH/DELETE run in this order: lock with FOR UPDATE, permission, version, validation, secrets, then the no-op check and the write. Node delete locks and deletes each edge (one row each) before the node. Unique violations become `ErrConflict`; an FK violation on edge insert becomes `body.from`/`body.to`.
- `internal/model/validate.go` and `secrets.go` (new): the attribute schema subset, the kind-pair check and `CheckSecrets`. All messages are fixed text.
- `internal/model/history.go` (new): `History`, with an `(at RFC3339Nano, id)` cursor. A bad cursor gives `query.cursor`.
- `internal/httpapi/routes_write.go` (new): the `Writer` interface, 12 operations registered through `register()` (Editor or Admin), `If-Match` parsing (`*`, weak or malformed → version 0, never matches), a 428 returned before the writer is called, and the `actorFrom(Principal)` mapping.
- `internal/httpapi/routes_model.go`: `Model.History`, the `get-history` operation (Viewer), and `entityFailure`, which maps 404/403/409/412/422 (validation and secret-detected) and in-use. A 500 logs only `operation` and `error_class`.
- `internal/httpapi/api.go`: the 5 new problem constants, `problemOf`, and `InUseProblem` (ErrorModel plus `count`, the 409 schema of both delete operations).
- `internal/httpapi/engine.go`: `Deps.Writer`. CORS now allows the `If-Match` header and exposes `ETag` (see Log). `serve.go` wires one `model.Service` as both `Model` and `Writer`.
- `api/openapi.yaml`: regenerated by `make openapi`.
- Tests: `internal/httpapi/routes_write_test.go` (new, fake writer that runs the real `CheckSecrets`), `routes_model_test.go` (`fakeModel.History`), `internal/model/validate_test.go` and `secrets_test.go` (new), `internal/db/db_test.go` (latest version is now 5).
- `cmd/arch-api/integration_test.go`: new `startPostgres` helper (creates `arch_app` before `db.Migrate` as `arch`), plus `newPool` and `newEngine` helpers. The existing read test and the seed now run as `arch_app`. `cmd/arch-api/write_integration_test.go` (new) covers writes, history and change_log protection.
- `README.md`: intro, a Database roles section, the config table, 13 new endpoint rows, a Writes section (If-Match/ETag, permissions, patches, attributes, secrets, problems table with `count`), paging, integration-test roles, the layout line, and Documents (spec 003, adr/0005).
- `internal/model/service.go`: package and type doc comments only.

### arch-web
- `src/api/schema.d.ts`: regenerated by `pnpm gen:api` from the arch-api worktree's `api/openapi.yaml`. No other file changes.

## Log
### Round 1
- Built the full spec in arch-api (6 commits) and arch-web (1 commit), pushed `factory/004-write-api-for-nodes`, and opened draft PRs CliXiD/arch-api#5 and CliXiD/arch-web#5, which link to each other.
- Decisions a reviewer should check:
  - **CORS** (`engine.go`): I added `If-Match` to `AllowHeaders` and exposed `ETag`. The spec doesn't list this. Without it, the browser SPA on `http://localhost:5173` (cross-origin to the API) can neither send `If-Match` nor read `ETag`, so the write contract could not be used from arch-web. It is not auth middleware. Revert it if you want it in a later job.
  - **`Principal.Username`** is in `internal/auth`, which is high risk. It is an added field only; role mapping and token validation are untouched.
  - **JSON `null` in PATCH**: Huma treats `null` for an optional PATCH field (e.g. `"name": null`) as absent, so that field is left unchanged rather than rejected with 422.
  - **No-op team and environment PATCH**: one that changes nothing writes no row, matching the node and edge rule. The spec is silent on this for teams and environments.
  - **`00005` Down**: it revokes `USAGE ON SCHEMA public` too, so it is a literal reversal, even though the hub's init script also grants it.
  - **Attribute checks on PATCH**: validation and the secret check run only when the PATCH includes `attributes`. Stored attributes were checked when they were written.
- I did not edit the hub documents listed under the spec's Docs impact (ADR-0014 status, a new ADR superseding ADR-0005, specs 001/003/008). I also did not do the follow-up that switches `dev/env/arch-api.env` to `arch_app`. Builders write only `build.md` in the hub, so these remain for the hub side.
