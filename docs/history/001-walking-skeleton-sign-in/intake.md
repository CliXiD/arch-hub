## Scope
Build the slice exactly as the issue's Behaviour and Contract describe, with the spec's paths read as relative to `/api/v1` (Decision 3; AGENTS.md already shows the API at `/api/v1`).

**arch-api** (greenfield Go module, gin + Huma v2, Go 1.27 per [ADR-0013]):
- `arch-api serve` and `arch-api migrate up|status`. Config from env ([SPEC-operations-05]): `DATABASE_URL`, `MIGRATE_DATABASE_URL` (optional, defaults to `DATABASE_URL`, used only by `migrate`, [ADR-0014]), `HTTP_ADDR`, `METRICS_ADDR`, `OIDC_ISSUER`, `OIDC_AUDIENCE`, `OIDC_JWKS_URL` (optional), `LOG_LEVEL`, `CORS_ORIGINS`, `OTEL_EXPORTER_OTLP_ENDPOINT` (optional), `OTEL_EXPORTER_OTLP_PROTOCOL`. A missing required variable stops start-up naming it. `.env.example` lists them with dummy values matching `dev/env/arch-api.env`.
- Public: `GET /healthz`, `GET /readyz` (DB ping + goose version equals latest embedded migration; `503` names `database` or `migrations`), `GET /metrics` on `METRICS_ADDR` only ([SPEC-operations-01], [-02]). Nothing else is public.
- JWT bearer auth on every `/api/v1` route per [SPEC-identity-access-02]: JWKS cached, refetched once on unknown `kid`, `iss`/`aud`/`exp` (30 s skew) checked; `401 /problems/unauthenticated`, `403 /problems/forbidden`, RFC 9457 `application/problem+json`. Roles from realm roles with `admin ⇒ editor ⇒ viewer` expansion; `teams` from the `teams` claim; `actor_kind: service` for client-credentials tokens ([SPEC-identity-access-03], [-07]).
- `GET /api/v1/me` (minimum role `viewer`) returning the shape in the issue Contract ([SPEC-identity-access-08]).
- Every route declares a minimum role; a unit test fails on any route without one ([NFR-001], Decision 10).
- One JSON `slog` line per request with the fields in [SPEC-operations-03]; never tokens, `Authorization` or bodies. OTel traces (gin + pgx, `service.name=arch-api`) only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set ([SPEC-operations-04]).
- goose migrations embedded in the binary with one empty baseline migration (Decision 4). No model tables.
- `api/openapi.yaml` generated by `make openapi`; `make openapi-check` compares against a temp file and never writes tracked files (Decision 12). `golangci-lint` pinned as a `tool` directive and run with `go tool golangci-lint run` (Decision 11). The repo must provide `go vet ./...`, `go tool golangci-lint run ./...`, `go test ./...`, `go build ./...`, `make openapi-check` — the hub's `factory/checks/arch-api.sh` already runs exactly these.
- GitHub Actions workflow running the same steps on every PR ([ADR-0010]).

**arch-web** (greenfield Vite + React 19 + TypeScript + Tailwind 4 + React Router 7 + TanStack Query + `oidc-client-ts`, Node 26 / pnpm per [ADR-0007], [ADR-0013]):
- Runtime config from `/config.json` (`apiBaseUrl`, `oidcAuthority`, `oidcClientId`), falling back to `VITE_API_BASE_URL`, `VITE_OIDC_AUTHORITY`, `VITE_OIDC_CLIENT_ID` when absent (Decision 5; matches `dev/env/arch-web.env`).
- Any route without a session → "Signing in…" and redirect to Keycloak (Authorization Code + PKCE), returning to the requested route; "Sign-in is unavailable, try again" with a "Try again" button when discovery fails ([SPEC-identity-access-01]).
- Signed-in shell: header "Architecture E2E", user menu with name, roles and teams from `GET /api/v1/me`, "Sign out" (RP-initiated logout, clears tokens); body "The landscape is coming soon." On `403` from `/me`: "You don't have access to Architecture E2E; ask an admin" ([SPEC-identity-access-03], [-08], [-09]).
- Silent refresh on expiry; failed refresh → back to sign-in and return to the same route ([SPEC-identity-access-09]). Tokens in memory only, never localStorage/sessionStorage.
- API calls carry `Authorization: Bearer` and a W3C `traceparent` header ([SPEC-operations-04]).
- `src/api/schema.d.ts` generated by `pnpm gen:api` from `arch-api/api/openapi.yaml` (never hand-edited). Scripts `lint`, `typecheck`, `test` (Vitest run mode), `build`, `gen:api` — the hub's `factory/checks/arch-web.sh` already runs the first four.
- GitHub Actions workflow with the same steps.

**Left out** (as the issue says): any model table, endpoint or screen; Dockerfiles, Helm and the realm export in `arch-deploy`; Playwright e2e and integration tests; the `arch` CLI; the prod OTLP backend. The hub's `dev/keycloak/arch-realm.json` and `dev/env/*.env` are used as-is and need no change.

**For the reviewers and approver:** this job necessarily creates files under the protected paths `arch-api/.github/*`, `arch-api/migrations/*` and `arch-web/.github/*`, and adds the auth middleware and three unauthenticated endpoints — all "always escalate" items in the Factory notes. That is expected for a first slice; both PRs are merged by a human. Merge order: `arch-api` first, then regenerate `schema.d.ts` in `arch-web`.

## Why
Both repos hold only a README and `.gitignore` (`repos/arch-api`, `repos/arch-web`), so this is the first code and every later spec depends on it; the issue's Decisions already cut it to Must items with no `arch-deploy` change. I checked the issue against the documents and the dev stack: `dev/keycloak/arch-realm.json` has realm roles `viewer`/`editor`/`admin` with composites, `viewer` as the default role, a `teams` group mapper (no path), an `arch-api` audience mapper on every client, and `arch-ci-platform` with a hardcoded `teams: ["platform"]` and the `editor` role — so the acceptance criteria about `teams: ["platform"]` and `actor_kind: "service"` are achievable as written. `dev/env/arch-api.env` and `dev/env/arch-web.env` use the exact variable names in the Contract (plus `MIGRATE_DATABASE_URL`, which the spec and [ADR-0014] require and I added), `dev/arch-api/start.sh` already calls `arch-api migrate up` then `serve`, and `factory/checks/arch-api.sh` / `arch-web.sh` already run the commands in Decision 13. Risk is high because it creates token validation, role mapping, public endpoints and a migration ([NFR-001], Factory notes "High risk").
