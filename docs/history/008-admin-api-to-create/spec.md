# Admin API for node and edge types

> Issue #19: Admin API to create and edit node and edge types

## Summary
- `arch-api` gets six admin-only operations under `/api/v1/admin/types`: create, update and delete for node types and for edge types ([BR-003], [SPEC-admin-01]).
- Every schema or allowed-pair change is checked against the existing nodes and edges. If any would fail, the API returns `409` with a `count` ([SPEC-admin-02]). Built-in types can gain attributes but can't lose them or be deleted ([SPEC-admin-03]). A custom type that is still in use can't be deleted ([SPEC-model-09]).
- Attribute schemas must use the documented JSON Schema subset ([SPEC-model-03]). Attribute names that look like secrets are rejected with `422 /problems/secret-detected` ([SPEC-model-10]).
- Each successful write appends one `change_log` row (entity `type`) in the same transaction ([SPEC-editing-history-06], [ADR-0016]). No migration is needed: 00004 already allows `entity = 'type'`, and 00005 already grants `arch_app` DML on both type tables.
- `arch-web` only regenerates `src/api/schema.d.ts` from the new `api/openapi.yaml` ([ADR-0003], [ADR-0007]).

## Context

**arch-api**
- Schema: `arch-api:migrations/00002_model.sql` defines `node_types (id CHECK ^[a-z0-9][a-z0-9-]{1,62}$, kind CHECK in 5 kinds, name, attributes_schema jsonb, builtin bool)` and `edge_types (id CHECK ^[a-z][a-z0-9_]{1,62}$, name, attributes_schema, allowed jsonb, builtin)`. `nodes.type` and `edges.type` are non-cascading foreign keys to these tables. `arch-api:migrations/00003_model_seed.sql` seeds the built-ins (`builtin = true`). `arch-api:migrations/00004_change_log.sql` allows `entity IN (..., 'type', ...)`, and `arch-api:migrations/00005_app_role_grants.sql` grants `arch_app` `SELECT, INSERT, UPDATE, DELETE` on `node_types` and `edge_types`. Migrations are protected and stay untouched.
- Read path: `arch-api:internal/model/service.go` `Service.Types` (queries `ListNodeTypes` and `ListEdgeTypes` in `arch-api:internal/db/queries/model.sql`) serves `GET /api/v1/types`, registered in `arch-api:internal/httpapi/routes_model.go`. API types `NodeType`, `EdgeType` and `KindPair` (with the kind `enum` tags) live in `arch-api:internal/model/types.go`.
- Write pattern to copy: `arch-api:internal/model/write.go`. It has `Service.inTx` (one transaction, rollback on any error) and `record(ctx, q, actor, entity, key, action, before, after)`, which writes the `change_log` row. It also has the team and environment admin writes: `CreateTeam` maps a unique violation to `ErrConflict`, `UpdateTeam` writes nothing on a no-op, and `DeleteTeam` returns `InUseError{Count}`. Node and edge writes read the type's schema with `q.GetNodeType` and `q.GetEdgeType` (`arch-api:internal/db/queries/write.sql`, used only in `write.go`) and check attributes with `validateAttributes` (`arch-api:internal/model/validate.go`) and the kind pair with `checkKindPair`.
- Errors: `arch-api:internal/model/errors.go` has `ErrNotFound`, `ErrConflict`, `ValidationError(s)`, `InUseError` and `SecretError`. `arch-api:internal/httpapi/routes_model.go` `entityFailure` maps these to problems, with `conflictDetail` giving the 409 detail per entity. `arch-api:internal/httpapi/api.go` defines the problem type constants and `InUseProblem{huma.ErrorModel; Count}`.
- Secrets: `arch-api:internal/model/secrets.go` provides `secretName` (regexp) and `secretNameToken(name)`. These are the name rules of [SPEC-model-10].
- Routes: `arch-api:internal/httpapi/routes_write.go` holds the `Writer` interface and `registerWriteRoutes`, where each operation is registered with `register(api, op, Admin, handler)`. Its `inUse()` helper adds the documented `409` response, and `actorFrom` builds the actor. A unit test (`arch-api:internal/httpapi/registry_test.go`) fails if any operation lacks a minimum role. `arch-api:internal/httpapi/routes_write_test.go` has `fakeWriter` and `TestWriteRoles`. The integration tests in `arch-api:cmd/arch-api/write_integration_test.go` (build tag `integration`) use the helpers `startPostgres`, `newEngine`, `writer.expect` and `changesSince`.
- Generated files: `make sqlc` regenerates `internal/db/dbq` and `make openapi` regenerates `api/openapi.yaml`. Neither is ever hand-edited. The endpoint table and the Writes section of `arch-api:README.md` document the API.

**arch-web**
- `arch-web:src/api/schema.d.ts` is generated by `pnpm gen:api` (`openapi-typescript ${ARCH_API_OPENAPI:-../arch-api/api/openapi.yaml}`). In the job worktree, `../arch-api` is this job's `arch-api` worktree. No UI uses types today.

## Contract

All operations sit under `/api/v1/admin/types`, use bearer auth with minimum role `admin`, and answer with RFC 9457 `application/problem+json`. A caller without a token gets `401`; a viewer or editor gets `403 /problems/forbidden` (existing middleware). The request bodies reject unknown fields, as every existing body does.

### Types

```ts
type Kind = "application" | "infrastructure" | "network" | "external" | "team";
type KindPair = { from: Kind; to: Kind };

// Attribute schema: the subset of [SPEC-model-03]. Nothing else is accepted.
type AttributesSchema = {
  type: "object";                              // required
  properties: { [name: string]: Property };    // required, may be {}
  required?: string[];                         // each a key of properties, no duplicates
  additionalProperties?: boolean;
};
type Property =
  | { type: "string"; enum?: string[] }                                  // enum non-empty
  | { type: "number"; enum?: number[]; minimum?: number; maximum?: number } // minimum <= maximum
  | { type: "boolean" }
  | { type: "array"; items: { type: "string" } };

// Responses reuse the existing model.NodeType / model.EdgeType shapes of GET /api/v1/types.
type NodeType = { id: string; kind: Kind; name: string; attributes_schema: AttributesSchema; builtin: boolean };
type EdgeType = { id: string; name: string; attributes_schema: AttributesSchema; allowed: KindPair[]; builtin: boolean };
```

### Operations

| op id | method, path | body | success |
|---|---|---|---|
| `create-node-type` | `POST /api/v1/admin/types/node-types` | `{id, kind, name, attributes_schema}`, all required; `id` matches `^[a-z0-9][a-z0-9-]{1,62}$`; `name` minLength 1 | `201` NodeType (`builtin: false`) |
| `create-edge-type` | `POST /api/v1/admin/types/edge-types` | `{id, name, attributes_schema, allowed}`, all required; `id` matches `^[a-z][a-z0-9_]{1,62}$`; `allowed` minItems 1, uniqueItems | `201` EdgeType (`builtin: false`) |
| `update-node-type` | `PATCH /api/v1/admin/types/node-types/{id}` | any of `{name, attributes_schema}`; each present field replaces the stored value whole | `200` NodeType |
| `update-edge-type` | `PATCH /api/v1/admin/types/edge-types/{id}` | any of `{name, attributes_schema, allowed}`; same rules | `200` EdgeType |
| `delete-node-type` | `DELETE /api/v1/admin/types/node-types/{id}` | none | `204` |
| `delete-edge-type` | `DELETE /api/v1/admin/types/edge-types/{id}` | none | `204` |

`id` and `kind` can't be changed. Sending them in a PATCH gives `422` at `body.id` / `body.kind`. A PATCH that changes nothing returns `200` with the stored type and writes no row.

Example: `POST /api/v1/admin/types/node-types`
```json
{"id":"message-broker","kind":"infrastructure","name":"Message broker",
 "attributes_schema":{"type":"object","properties":{"engine":{"type":"string","enum":["rabbitmq","kafka"]}}}}
```
→ `201 {"id":"message-broker","kind":"infrastructure","name":"Message broker","attributes_schema":{...},"builtin":false}`

### Errors

| status | `type` | when | extra |
|---|---|---|---|
| 403 | `/problems/forbidden` | role below admin | |
| 404 | `/problems/not-found` | PATCH or DELETE of an unknown id; detail `node type not found` / `edge type not found` | |
| 409 | `/problems/conflict` | create with an id already in that table | detail `a node type with this id already exists` / `an edge type with this id already exists` |
| 409 | `/problems/conflict` | built-in type: DELETE, or a PATCH whose `attributes_schema` drops a property the stored schema declares | detail `built-in types can't be deleted` / `built-in types can't lose attributes`, no `count` |
| 409 | `/problems/conflict` | PATCH whose new `attributes_schema` would fail one or more existing nodes/edges of the type (`validateAttributes`), or, for edge types, whose new `allowed` drops a pair that existing edges use | `count`: number of distinct nodes (node type) or edges (edge type) that fail; detail `existing nodes would fail the change` / `existing edges would fail the change` |
| 409 | `/problems/in-use` | DELETE of a custom type that nodes (node type) or edges (edge type) still use | `count`: number of those nodes or edges; detail `node type is still used by nodes` / `edge type is still used by edges` |
| 422 | `/problems/validation` | bad id pattern, unknown kind (in `kind` or `allowed`), empty name, `allowed` empty or with duplicates, `attributes_schema` outside the subset | one `errors[]` entry per bad field; schema errors sit at `body.attributes_schema`, `body.attributes_schema.properties.<name>` or `body.attributes_schema.required` |
| 422 | `/problems/secret-detected` | a key of `attributes_schema.properties` matches the [SPEC-model-10] name rules | one `errors[]` entry per name: location `body.attributes_schema.properties.<name>`, message `looks like a secret` |

The 409 responses that carry `count` use the existing `InUseProblem` schema (`ErrorModel` + `count: integer`), and the OpenAPI document lists it on the PATCH and DELETE operations. Problems never echo the submitted values.

### change_log

Every successful create, update or delete appends exactly one row through `record()`. The row has `entity = 'type'` and `entity_key` `node/<id>` for node types or `edge/<id>` for edge types. `action` is `create`, `update` or `delete`. `before` and `after` hold the NodeType/EdgeType API JSON (`null` on create/delete respectively). `source` is `ui`, as for every write through the API today. A rejected write leaves no row.

### Schema, env, compatibility
- No table or column changes, so no migration. No new env var or config.
- Additive only: `GET /api/v1/types` and every existing operation keep their shapes. `InUseProblem.count`'s doc text widens to "nodes or edges". Deployed `arch-web` keeps working before regenerating. The YAML schema (`arch-api:schema/`) is unchanged, so existing team files stay valid (Decision 5).

## Requirements

### arch-api
1. Add the body types `NodeTypeCreate`, `EdgeTypeCreate`, `NodeTypePatch` and `EdgeTypePatch` to `internal/model/types.go`, using Huma tags (`pattern`, `enum` via `KindPair`/kind, `minLength`, `minItems`, `uniqueItems`, `nullable:"false"`) so the request-shape errors of the Contract come from Huma as `422 /problems/validation`.
2. Add `validateSchema(schema map[string]any) ValidationErrors` to `internal/model/validate.go`. It accepts exactly the subset in the Contract (`type: "object"`, `properties`, `required`, `additionalProperties`; per property `type` of string/number/boolean/array, `enum` (string or number only, non-empty, values of the property's type), `minimum`/`maximum` (number only, minimum <= maximum), `items: {type: "string"}` (array only, required)). It rejects empty property names, unknown keywords, `required` names that aren't declared properties, and duplicates in `required`, returning fixed messages ordered by location. Every seeded schema in `00003_model_seed.sql` must pass it.
3. Add `checkSchemaSecrets(schema)` to `internal/model/secrets.go`. It returns a `*SecretError` naming `body.attributes_schema.properties.<name>` for each property name matching `secretName` or `secretNameToken`, and must reuse those two rules rather than copy them. Run it after `validateSchema` succeeds, as `CreateNode` runs `CheckSecrets` after validation.
4. Add sqlc queries in a new file `internal/db/queries/types.sql`: create, lock (`FOR UPDATE`), update (name, attributes_schema[, allowed]) and delete per type table; count nodes / edges of a type; list the `attributes` of every node / edge of a type; count the edges of a type whose (from-node kind, to-node kind) pair isn't in a given allowed set (or list their kind pairs and compare in Go). Then run `make sqlc`.
5. Change `GetNodeType` and `GetEdgeType` in `internal/db/queries/write.sql` to `FOR SHARE`. A node or edge write then holds the type row while it validates, and a type update's `FOR UPDATE` lock waits for it (and the reverse). That way, no node or edge can be written against a schema that is being replaced. Regenerate with `make sqlc`.
6. Add `CreateNodeType`, `UpdateNodeType`, `DeleteNodeType`, `CreateEdgeType`, `UpdateEdgeType` and `DeleteEdgeType` to `model.Service` in a new file `internal/model/types_write.go`, each in `s.inTx` and following the team writes:

   - Update: lock the type row (`ErrNotFound` if absent), then validate and secret-check a present `attributes_schema`. For a built-in, a new schema that lacks any property key of the stored schema gives `ErrBuiltin` (new sentinel). If the schema changed, run `validateAttributes` against every existing node/edge of the type. If `allowed` changed, check every existing edge's kind pair against the new set. If any item fails, return `IncompatibleError{Count}` (new type in `errors.go`), counting each failing item once. An unchanged result writes nothing (compare with `sameJSON`). Otherwise update the row and record `update` with before/after.
   - Delete: lock the type row (`ErrNotFound`). A built-in gives `ErrBuiltin`. If the count of nodes/edges using it is above 0, return `InUseError{Count}`. Otherwise delete the row and record `delete`. A foreign-key violation from a concurrent insert also maps to `InUseError` (re-count).

## Out of scope
- The `/admin/types` web page and any UI in `arch-web` beyond the regenerated file.
- Changing a node type's `kind` or any type's `id`. No rename endpoint and no expand/contract.
- Any change to the YAML JSON Schema (`arch-api:schema/`), import or export.
- New migrations, grants, or changes to `change_log` columns, triggers or grants.
- Secret checks on enum values, default values, or any JSON Schema keyword beyond the subset (`description`, `default`, `pattern`, `format`, nested objects).
- A history endpoint for types (`GET /history?entity=type`). The rows are written but not queried in this job.
- Per-environment types (Decision 4: types stay global).
- Changing `source` handling (for example `api` for service accounts) or the auth middleware and role mapping.

## Assumptions
- `entity_key` for types is `node/<id>` / `edge/<id>`. Node and edge type ids may collide (`calls` fits both patterns), and neither [SPEC-editing-history-06] nor [ADR-0016] defines a key.
- Schema-incompatibility 409s use `/problems/conflict` with `count` (the `InUseProblem` shape). The issue names no problem type for Behaviour 3, and `/problems/in-use` means "can't delete while used".
- Built-in 409s (delete, losing a declared attribute) use `/problems/conflict` without `count`, as intake suggested. "Lose attributes" means dropping a property key; changing a built-in property's definition is allowed when existing data still passes.
- A built-in type's display `name` may change. "Renamed" in [SPEC-admin-03] and the issue's "renamed (id)" refer to the id.
- `attributes_schema` is required on create, and `allowed` needs at least one pair with no duplicates. An edge type with no pair could never be used. A strict body is the smallest contract.
- Removing an attribute from a custom type is allowed, subject to the existing-data check (it fails only when `additionalProperties: false` and nodes hold it).
- `GetNodeType`/`GetEdgeType` become `FOR SHARE`. Without that lock, a node or edge written concurrently against the old schema would slip past the existing-data check (high-risk area). `arch_app` already has `UPDATE`, which `FOR SHARE` requires.
- `source` on the type `change_log` row is `ui`, the value `record()` writes for every API write in this codebase.
